## 4. 지적사항 서술 문법

`지적사항` 필드는 자유 서술이 아니라 일정한 형식을 따른다. 265건 중 255건(96%)이
아래 패턴에 부합한다.

```
25상-3(조치필요) 외부 계단 벽체 망상균열
─────  ────────  ──────  ────  ──────
 회차    등급      위치    부재   상태
```

**실제 예시**
```
25하-3(조치필요)  2층 외부 벽체 도장박락, 열화
25상-11(조치필요) 지붕층 바닥 구배불량 및 물고임
25상-12(조치필요) 2층 관람석 난간 녹오염, 부식
25하-1(조치필요)  외부 주출입구 계단 미끄럼방지시설 미설치
25상-5(조치필요)  외부 출입문(1~10문) 상부 벽체 전도 위험
25상-2(조치필요)  1층 상부 콘크리트 보 박락
```

이 문법을 판정 결과의 **소견 출력 형식으로 고정**하였다. 생성된 소견이 실제 점검 문서와
동일한 어법을 갖게 되어, 자율안전점검 기록 초안으로 바로 활용 가능하다.

### 회차 코드
`25상-3` = 2025년 상반기 3차. `24하`, `23-4` 등 이전 회차도 소수 포함.

## 7. 판정 성능 검증 (게이트 1)

### 방법
공식 점검항목 22종을 분류체계로 주입하고, 다중 라벨 + 확신도 + 소견 생성을 요구하는
프롬프트로 멀티모달 LLM에 판정을 의뢰. 두 집단을 비교하였다.

- **집단 A**: 스마트폰 직접 촬영 8장 (실사용 조건 재현)
- **집단 B**: 공단 개방 이미지 3장 (039, 040, 041)

### 결과

| 집단 | 적합 | 보완필요 | 최고 확신도 | 주된 실패 원인 |
|---|---|---|---|---|
| A (직접 촬영) | 5 | 3 | 0.85 | 촬영 구도 (사선 각도, 과도한 근접) |
| B (공단 이미지) | 0 | 3 | 0.70 | **해상도 자체의 한계** |

### 해석

**1. 판정 체계는 작동한다.**
새로운 항목을 생성하지 않고 22종 공식 명칭을 정확히 사용했으며, 소견이 공단 지적사항
문법을 재현했다.

```
생성:  건물 외부 창호 하부 창대 콘크리트 탈락, 철근 노출 및 부식
원본:  25상-3(조치필요) 외부 계단 벽체 망상균열
```

**2. 다중 라벨은 필수다.**
11장 전체에서 단일 항목으로 귀결된 사례가 없었다. 모든 사진이 2~3개 항목에 걸쳤다.
`철골재 부식`과 `마감재파손`, `균열, 누수`와 `마감재파손`처럼 원 분류체계 자체가
현상·부재·기능 기준이 혼재되어 있기 때문이다. 단일 선택을 강제하면 오답률이 급증한다.

**3. 공단 이미지는 판정 입력으로 쓸 수 없다.**
집단 B의 실패 원인은 구도가 아니라 화질이었다. 도장 박리인지 하지재 탈락인지, 마감재
결손인지 시공 시 앵커 구멍인지를 구분할 표면 질감이 해상도에 소실되어 있다.
→ 공단 이미지는 판정 입력이 아닌 **결과 화면의 참조 사례**로 용도를 한정한다.

**4. 부재 특정 실패가 반복 관찰된다.**
"주요구조부인지 비구조부인지 사진만으로 미확정", "금속 부재가 난간 지주인지 볼라드인지
특정 불가" 유형의 실패가 다수 발생했다.
→ ① 입력 단계에서 건물구분·위치구분을 선택받고, ② 확신도가 낮으면 전경 사진 추가
촬영을 요청하는 흐름으로 흡수한다.

### 설계 확정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 자체 모델 학습 | 하지 않음 | 265건, 바운딩 박스 부재 |
| 이미지 임베딩 검색 | 사용하지 않음 | 265장으로는 커버리지 부족 |
| few-shot 시각 예시 | 사용하지 않음 | 공단 이미지 화질이 오히려 노이즈 |
| 외부 이미지 데이터셋 | 사용하지 않음 | 학습을 하지 않으므로 실익 없음 |
| 판정 기준 | 공단 점검항목 22종 텍스트 | 검증 완료 |
| 출력 형식 | 다중 라벨 + 확신도 + 공단 서술 문법 | 검증 완료 |

### 미확보 항목
집단 A 촬영분은 콘크리트·석재 계열에 편중되어, 다음 항목의 표본이 없다.

```python
# 이미지 일괄 수집 — scripts/download_images.py
# 이미 받은 파일은 건너뛰므로, 재실행하면 누락분만 보충된다.
import csv, os, ssl, urllib.request
from concurrent.futures import ThreadPoolExecutor

BASE = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "data")
CSV = os.path.join(BASE, "defects.csv")
OUT = os.path.join(BASE, "images")

# data.csv는 CP949, data_utf8.csv는 UTF-8 — 어느 쪽이 넘어와도 읽히게 한다.
def read_rows(path):
    for enc in ("utf-8-sig", "cp949"):
        try:
            with open(path, encoding=enc) as f:
                return list(csv.DictReader(f))
        except UnicodeDecodeError:
            continue
    raise SystemExit(f"인코딩을 판별할 수 없음: {path}")

# 서버가 http -> https로 301 리다이렉트하는데 인증서 검증이 실패해서 검증을 끈다.
ctx = ssl.create_default_context()
ctx.check_hostname = False
ctx.verify_mode = ssl.CERT_NONE

def fetch(row):
    name = row["이미지파일이름"].strip()
    url = row["이미지URL"].strip().rstrip("/") + "/" + name
    path = os.path.join(OUT, name)
    if os.path.exists(path) and os.path.getsize(path) > 0:
        return ("skip", name, "")
    try:
        req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
        with urllib.request.urlopen(req, timeout=30, context=ctx) as resp:
            data = resp.read()
        if not data:
            return ("fail", name, "empty body")
        with open(path, "wb") as f:
            f.write(data)
        return ("ok", name, len(data))
    except Exception as e:
        return ("fail", name, repr(e))

def main():
    os.makedirs(OUT, exist_ok=True)
    rows = read_rows(CSV)
    with ThreadPoolExecutor(max_workers=8) as ex:
        results = list(ex.map(fetch, rows))

    counts = {k: sum(1 for r in results if r[0] == k) for k in ("ok", "skip", "fail")}
    print(f"total={len(results)} ok={counts['ok']} skipped={counts['skip']} failed={counts['fail']}")
    for status, name, detail in results:
        if status == "fail":
            print("FAIL:", name, detail)

if __name__ == "__main__":
    main()
```

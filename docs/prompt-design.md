# 판정 프롬프트 설계

체육시설 안전점검 보조 서비스의 결함 판정 프롬프트. 2026-09-14 게이트 1 검증 결과를 반영한 확정본.

---

## 설계 원칙

| 항목 | 결정 | 근거 |
|---|---|---|
| 분류 체계 | 공단 공식 점검항목 22종 그대로 | 대체 불가 자산, 새 항목 생성 금지 |
| 라벨 개수 | 다중 라벨 (최대 3) + 확신도 | 검증 11장 전부 2~3개 항목에 걸침 |
| few-shot 이미지 | 사용하지 않음 | 공단 이미지 해상도가 오히려 노이즈 |
| 소견 형식 | `[위치] [부재] [상태]` 고정 | 공단 지적사항 서술 문법 재현 |
| 판정 불가 | 명시적으로 허용 | 억지 분류 방지 |
| 확신도 임계 | 0.5 미만 → 재촬영 요청 | 부재 특정 실패가 반복 관찰됨 |

```
## 판정 규칙

1. 사진 한 장이 복수 항목에 해당하는 것이 일반적입니다.
   최대 3개까지 제시하고, 각각에 확신도(0.0~1.0)를 부여하십시오.

2. 분류 체계가 현상·부재·기능 기준으로 혼재되어 있습니다.
   예: 난간에 부식이 있으면 11번(난간)과 3번(철골재 부식)에 모두 해당합니다.
   억지로 하나로 좁히지 말고 모두 제시하십시오.

3. 확신이 없으면 낮은 확신도를 부여하거나 판정하지 마십시오.
   "판정 불가"를 정직하게 내는 것이 잘못된 분류보다 낫습니다.

4. 22개 항목 어디에도 해당하지 않으면 판정 배열을 비우고
   그 사실을 noticeText에 기술하십시오.

5. 부재를 특정할 수 없으면(예: 금속 부재가 난간 지주인지 볼라드인지
   불명) 확신도를 0.4 이하로 낮추십시오.

## 소견 작성 규칙

공단 점검관의 서술 문법을 따릅니다.

    [위치] [부재] [상태]

실제 사례:
    외부 계단 벽체 망상균열
    2층 외부 벽체 도장박락, 열화
    지붕층 바닥 구배불량 및 물고임
    2층 관람석 난간 녹오염, 부식
    외부 주출입구 계단 미끄럼방지시설 미설치
    1층 상부 콘크리트 보 박락

- 명사형으로 끝냅니다. "~습니다", "~됨" 등 서술형 어미를 쓰지 마십시오.
- 위치는 사용자가 선택한 건물구분·위치구분을 우선 반영합니다.
- 상태는 관찰된 현상만 기술합니다. 원인 추정이나 조치 권고는 넣지 않습니다.

## 출력 형식

반드시 아래 JSON만 출력하십시오. 마크다운 코드펜스, 설명, 서문을
붙이지 마십시오.

{
  "defectObserved": "YES" | "NO" | "UNCERTAIN",
  "judgements": [
    {
      "itemId": 1,
      "itemName": "균열, 누수",
      "confidence": 0.82,
      "evidence": "판정 근거를 한 문장으로"
    }
  ],
  "notice": "[위치] [부재] [상태] 형식의 소견",
  "imageQuality": {
    "sufficient": true,
    "issue": "부족한 경우에만 사유를 기술, 충분하면 빈 문자열"
  },
  "needsWiderShot": false,
  "noticeText": "22개 항목에 해당하지 않거나 특이사항이 있을 때만 기술"
}

- judgements는 confidence 내림차순 정렬
- defectObserved가 "NO"이면 judgements는 빈 배열
- needsWiderShot: 부재 특정이 어려워 전경 사진이 필요하면 true
```

## 사용자 메시지 구성

```
건물구분: {건물 내외부 | 건물주변}
위치구분: {선택값}

위 위치에서 촬영한 사진입니다. 판정하십시오.
[이미지]
```

### 위치구분 선택지 (공단 데이터 기준)

CSV의 `위치구분` 고유값을 그대로 사용합니다. 주요 12종:

| 위치구분 | 사례 수 |
|---|---|
| 기둥 보 바닥 벽 계단 (주요구조부) | 77 |
| 창호 | 25 |
| 옥상 / 지붕 | 22 |
| 바닥 벽(내외부) 천정, 계단(비구조부) | 20 |
| 계단 경사로 | 20 |
| 통행로 | 20 |
| 난간 | 18 |
| 부대시설 | 17 |
| 부착물 | 15 |
| 옹벽 / 노후축대 | 11 |
| 절개지 / 낙석 위험지역 | 7 |
| 승강기 등 | 6 |

> 전체 15종. 나머지 3종은 CSV에서 `df["위치구분"].unique()`로 확인하여 채울 것.

건물구분과 위치구분을 함께 주면 판정 후보가 좁혀져 정확도가 오릅니다.
검증에서 "주요구조부인지 비구조부인지 사진만으로 미확정" 유형의 실패가
반복 관찰되었으므로, 이 입력은 선택이 아니라 필수로 설계합니다.

## 후처리 로직

### 1. 확신도 임계 처리

```java
double top = result.judgements().isEmpty()
        ? 0.0
        : result.judgements().get(0).confidence();

if (result.needsWiderShot() || top < 0.5) {
    // 재촬영 안내
    // "이 사진만으로는 부재를 특정하기 어렵습니다.
    //  조금 물러서서 주변이 함께 보이는 사진을 한 장 더 올려주세요."
}
```

**이 기능이 독창성 근거입니다.** 실제 검증에서 발견한 실패 유형(과도한 근접,
사선 각도로 인한 부재 미특정)을 UX로 흡수한 것으로, 보고서에 명시할 것.

### 2. 사례 조회

판정된 `itemId`로 공단 265건 중 동일 항목 사례를 조회하여 함께 노출합니다.

```
── 공단 점검 사례 ──────────────
[썸네일]  2층 외부 벽체 도장박락, 열화
[썸네일]  1층 상부 콘크리트 보 박락
```

- 시설명·주소는 노출하지 않습니다 (특정 시설 지목 회피)
- 희소 항목(사례 1~2건)은 "해당 유형의 공개 사례가 적습니다" 표기

### 3. 결과 캐싱

이미지 SHA-256 해시를 키로 판정 결과를 캐싱합니다. 동일 이미지 재호출을
차단하여 비용과 응답 시간을 모두 줄입니다.

## 개선 대기 항목

배포 이후 여유가 있을 때 검토할 사항.

- 22개 항목을 6개 대분류로 묶어 2단계 판정 (대분류 → 소분류) 시도
- 희소 항목(사례 7건 이하)의 판정 정확도 별도 측정
- 철골 계열 3종, 체육시설 특화 3종 표본 확보 후 재검증 (9/22 촬영 시)
- 공식 Java SDK(com.anthropic:anthropic-java) 전환 검토. 현재는 RestClient로 직접 호출하며 재시도·사용량 기록·캐시 지시를 직접 제어한다. 스트리밍이나 타입 안전한 응답 처리가 필요해지면 재검토한다.

### 원문 보존 원칙

공단 개방 데이터에는 일부 표기 오류가 있다. 예를 들어 점검항목 6번은
"마감재의 파손(균열, 탈락), 오염, 누수 및 누수, 침수 흔적의 발생 여부"로
'누수'가 중복 기재되어 있다.

본 서비스는 이를 임의로 수정하지 않고 원문 그대로 사용한다. 공공데이터
활용 사례로서 원본과의 대조 가능성을 유지하는 것이 우선이며, 판정 결과의
근거가 공단 원문임을 보장하기 위함이다. 정제가 필요한 항목은 별도로 식별하여
보고한다.

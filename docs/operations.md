# 운영 설계

판정 모델 호출은 서비스에서 비용이 발생하는 유일한 지점이다. 이 문서는 공개 URL로
운영하면서 비용과 가용성을 지키는 방법, 사용자 정보를 다루는 방식, 배포 구성을
정리한다. 판정 방식 자체는 `prompt-design.md`, 공단 데이터는 `data-analysis.md`를
참조한다.

---

## 1. 비용 통제

여러 겹으로 나눠, 앞 단계가 대부분을 흡수하고 뒤 단계는 최후 방어선이 되도록 했다.

| 단계 | 방식 | 효과 |
|---|---|---|
| 이미지 축소 | 장변 1024px로 줄여 전송 | 입력 토큰 감소 |
| 프롬프트 캐싱 | 매 요청 동일한 시스템 프롬프트(점검항목 22종 포함)를 캐시 | 반복 입력 비용 약 90% 절감 |
| 응답 캐시 | 같은 사진·같은 위치 선택이면 모델을 호출하지 않음 | 반복 요청 비용 0 |
| 호출 제한 | 접속 주소별 시간당 상한, 전체 일일 상한 | 하루 비용 상한 고정 |
| 지출 한도 | 모델 제공사 콘솔의 월 한도 | 최후 방어선 |

### 실측 (2026-09-20)

| 항목 | 값 |
|---|---|
| 요청당 토큰 | 입력 약 1,100 / 캐시된 시스템 프롬프트 2,424 / 출력 350~830 |
| 응답 시간 | 5~11초 |
| 요청당 비용 | 첫 호출 약 15원, 이후 약 9원 |

당초 예상(요청당 24원) 대비 약 60% 절감. 일일 상한 300회 기준 하루 최대 비용은
약 2,700원이다.

## 2. 호출 제한

### 기준

| 구분 | 상한 | 목적 |
|---|---|---|
| 접속 주소별 | 시간당 20회 | 한 사용자가 전체 몫을 소진하지 못하게 한다 |
| 전체 | 하루 300회 (한국 시간 자정 초기화) | 하루 비용을 묶어둔다 |

- **실제 모델 호출만 센다.** 캐시 적중은 비용이 없으므로 차감하지 않는다.
- 두 상한 중 하나라도 넘으면 아무것도 차감하지 않고 거부한다.
- 거부 시 HTTP 429와 `Retry-After`, 남은 대기 시간을 담은 안내 문구를 돌려준다.
- 주소별 상한을 넉넉히 둔 이유: 같은 기관 네트워크에서 여러 명이 접속하면 주소
  하나로 묶인다. 비용은 전체 상한이 지키므로, 주소별 상한은 반복 호출만 막으면 된다.

### 접속 주소 판별

Cloud Run 앞단 프록시를 거치므로 연결 주소는 프록시 주소가 된다. 프록시가
`X-Forwarded-For`의 **맨 뒤**에 붙인 값을 실제 접속 주소로 쓴다. 맨 앞 값은
클라이언트가 임의로 넣을 수 있어 쓰지 않는다.

국내 이동통신망은 대부분 IPv6로 접속한다. IPv6는 기기가 주소 뒤 64비트를
주기적으로 바꾸므로, 주소 전체를 키로 쓰면 같은 사용자가 한도를 새로 받는다.
**IPv6는 앞 64비트, IPv4는 주소 그대로**를 한 사용자로 본다.

| 확인 (2026-09-22) | 결과 |
|---|---|
| 노트북, 와이파이 | IPv4. 프록시 접속 기록의 주소와 판별 결과 일치 |
| 휴대폰, 같은 와이파이 | 노트북과 같은 주소로 묶임 |
| 휴대폰, LTE | IPv6. 와이파이와 다른 사용자로 구분됨 |

### 한계와 확장

접속 주소는 사용자를 정확히 구분하지 못한다. 같은 네트워크의 여러 사람은 하나로
묶이고, 네트워크를 바꾸면 새 사용자가 된다. 로그인이 없는 현재 단계에서 별도
식별값을 만들지 않고 쓸 수 있는 가장 단순한 기준으로 택했다.

현재는 접속 주소 기준으로 호출을 제한하며, 운영 기관의 계정 체계와 연계하면
시설·운영자 단위 제한으로 전환할 수 있도록 설계했다. 호출 제한 로직은 문자열 키
하나만 받고, 키를 만드는 방식은 `ClientIpResolver`에만 있다. 계정이 도입되면
컨트롤러에서 키를 만드는 부분만 바꾸면 된다.

## 3. 사용자 정보 처리

| 정보 | 처리 |
|---|---|
| 업로드 사진 | 판정을 위해 AI 모델로 전송. 서버에 저장하지 않는다 |
| 사진 해시 | 응답 캐시 키로 메모리에 보관 (최대 1,000건, 24시간) |
| 접속 주소 | 호출 제한을 위해 메모리에 최대 1시간 보관. 재배포 시 사라진다 |
| 애플리케이션 로그 | 접속 주소를 남기지 않는다. 경고 로그는 가린 형태로만 남긴다 |
| 플랫폼 접속 기록 | Cloud Run이 요청마다 자동 기록 (Cloud Logging 기본 보관 30일) |

사진을 올리는 단계와 결과 화면 하단에 사진 전송, 임시 보관, 주소 보관 방식을 안내한다.

## 4. 배포 구성

| 항목 | 설정 | 이유 |
|---|---|---|
| 리전 | asia-northeast3 (서울) | 국내 사용자 지연 최소화 |
| 인스턴스 | 최소 1, 최대 1 | 최소 1은 첫 요청 지연 방지. 최대 1은 캐시와 호출 제한이 메모리에 있어 인스턴스가 늘면 둘 다 갈라지기 때문 |
| 메모리 | 1GiB | 휴대폰 원본(약 4000×3000)을 풀면 한 장에 약 48MB, 처리 중 복사본이 생긴다 |
| API 키 | Secret Manager에서 환경변수로 주입 | 배포 명령과 콘솔에 키가 노출되지 않는다 |

### 주의

재배포하면 새 인스턴스가 뜨므로 **응답 캐시와 호출 제한 기록이 초기화**된다.
기능 동결(2026-09-27) 이후에는 배포하지 않는다. 설정값 변경도 새 리비전을
만들므로 같은 원칙을 따른다.

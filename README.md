# SafeCheck — 체육시설 자율안전점검 AI 보조 서비스

국민체육진흥공단이 개방한 체육시설 안전점검 데이터를 기반으로, 시설 사진 한 장에서
공식 점검항목 판정과 점검 소견 초안을 생성하는 웹 서비스.

> 2026년 국민체육진흥공단 공공데이터 활용 경진대회 — 서비스(앱·웹) 개발 부문 출품작

- 서비스 주소: https://safecheck-kspo-682633822319.asia-northeast3.run.app
- 최초 배포: 2026-09-14

---

## 문제 인식

공단이 관리하는 정상 운영 체육시설 71,874개소 중 82.1%인 59,019개소가 자율안전점검
대상이며, 모두 체육도장·체력단련장·당구장·골프연습장 같은 소규모 신고 체육시설업이다
(공단 안전점검 정보 `자율점검대상여부` 기준). 이 시설들은 운영자가 스스로 안전점검을
수행해야 한다.

그러나 전문 점검 인력을 상시 두기 어려운 소규모 시설에서는, 점검 항목을 해석하고 발견한
결함을 규정된 형식으로 기록하는 일 자체가 진입 장벽이 된다.

공단은 2026년 「AI기반 체육시설 안전점검 및 학습데이터 구축 용역」을 통해 AI가 점검
사진을 분석해 손상을 자동 탐지하고, 그 결과를 학습데이터로 가공·개방하여 AI 안전점검
분야의 산업 발전에 기여하는 것을 과업 목적으로 명시한 바 있다. 본 서비스는 그 개방
데이터를 실제로 활용한 민간 서비스 사례를 목표로 한다.

## 서비스 개요

```
① 위치 선택      건물구분(2종) → 위치구분(15종), 시설 종류(선택)
       ↓
② 사진 업로드     현장에서 촬영한 시설 사진
       ↓
③ 판정           공단 공식 점검항목 22종 기준, 다중 라벨 + 확신도
       ↓
④ 소견 생성       공단 지적사항 서술 문법 "[위치] [부재] [상태]" 적용
       ↓
⑤ 근거 제시       공단 실제 점검 사례(동일 항목) 사진 및 지적사항 문구
       ↓
⑥ 등급 현황       같은 업종 시설의 공단 안전점검 등급 분포 (참고 통계)
```

확신도 최고값이 임계치 미만이면 부재 특정이 어렵다고 판단하여, 전경 사진 추가 촬영을
사용자에게 요청한다. 이는 실제 테스트에서 반복 관찰된 실패 유형을 기능으로 흡수한 것이다.

등급 현황은 다른 시설들의 공단 점검 결과이며, 사용자 시설의 등급을 매기지 않는다.

## 활용 공공데이터

공공데이터포털(data.go.kr)에서 확보하였으며, 이용허락범위는 모두 **제한 없음**이다.

| 데이터명 | ID | 형태 | 활용 내용 |
|---|---|---|---|
| 서울올림픽기념국민체육진흥공단_체육시설 안전점검 결함사진 학습 데이터_20251231 | 15157025 | CSV + 이미지 | 공식 점검항목 22종 체계(판정 기준), 지적사항 서술 문법(소견 형식), 결함 사례 265건(근거 제시) |
| 서울올림픽기념국민체육진흥공단_전국체육시설 안전점검 정보 | 15107773 | REST API | 전국 98,622건 수집, 정상 운영 중이며 등급이 공개된 55,051개소의 시설 구분·업종별 종합등급 분포(등급 현황), 업종별 자율안전점검 대상 여부 |

두 데이터를 개별 시설 단위로 연결하지 않고, 각자 다른 역할로 결합했다.
결함사진 데이터는 **무엇을 어떻게 판정할지**, 안전점검 정보는 **같은 업종 시설들이
실제로 어떤 등급을 받는지**를 제공한다.

활용신청 후 검토했으나 사용하지 않은 데이터와 그 사유는
[`docs/data-analysis.md`](docs/data-analysis.md) 하단 이력에 기록했다.

## 데이터 분석 요약

원본 데이터를 그대로 사용하지 않고 전수 분석 후 활용 가능한 형태로 재구성하였다.

| 확인 사항 | 내용 | 설계 반영 |
|---|---|---|
| 공식 점검항목 22종 | `점검항목`과 `결함유형`이 1:1 대응 | 판정 분류체계로 직접 채택 |
| 3단 위치 체계 | 건물구분(2) → 위치구분(15) → 점검항목(22) | 입력 폼 구조로 반영 |
| 지적사항 서술 문법 | `[회차](등급) [위치] [부재] [상태]` | 소견 생성 출력 형식으로 고정 |
| 이미지 해상도 | 중앙값 330×248, 최대 476px | 판정 입력이 아닌 참조 사례로 용도 한정 |
| 조치등급 편중 | `(조치필요)` 259/265 (97.7%) | 심각도 신호로 사용 불가, 제외 |
| 안전점검 등급 모집단 | 55,051개소, 신고 체육시설업 81.8% | 시설 구분 → 업종 순으로 선택 |
| 구분별 주의 비율 | 신고업 2.3%, 공공 10.4%, 등록업 23.9% | 같은 업종·구분·전체를 나란히 비교 |
| 자율안전점검 대상 | 정상 운영 시설의 82.1%, 6개 업종 | 대상 업종 선택 시 안내 |

## 기술 구성

| 영역 | 선택 | 비고 |
|---|---|---|
| 백엔드 | Java 21 / Spring Boot 4 | |
| 판정 엔진 | 멀티모달 LLM API (Claude Sonnet 5) | 자체 모델 학습 없음 |
| 데이터 | JSON 파일, 기동 시 메모리 적재 | 점검항목 22종, 사례 265건, 등급 분포 집계 |
| 배포 | Google Cloud Run (asia-northeast3) | 인스턴스 1개 고정, API 키는 Secret Manager |
| 프론트엔드 | 단일 페이지 (HTML·CSS·JS) | 백엔드에서 정적 서빙, 빌드 단계 없음 |

자체 AI 모델을 학습하지 않고, 범용 멀티모달 모델의 시각 인식 능력에 **공단이 정의한
판정 체계와 서술 규칙을 주입**하는 구조를 택했다. 공단 개방 데이터가 265건 규모로
모델 학습에는 부족하나, 판정 기준 데이터로는 충분하다는 분석 결과에 따른 설계다.

## 실행 방법

```bash
# 프로젝트 루트 .env
LLM_API_KEY=...            # 판정 모델 API 키

# 모델을 호출하지 않는 개발용 (비용 없음)
./gradlew bootRun --args='--spring.profiles.active=mock'

# 실제 모델 호출
./gradlew bootRun

# 테스트
./gradlew test
```

공공데이터 집계 파일을 다시 만들 때는 `docs/data-analysis.md` 부록의 재현 절차를 따른다.

## 면책

본 서비스의 판정 결과는 자율안전점검 수행을 보조하기 위한 참고 자료이며, 체육시설법에
따른 정식 안전점검이나 정밀안전진단을 대체하지 않는다. 구조적 위험이 의심되는 경우
반드시 전문 점검기관의 진단을 받아야 한다.
